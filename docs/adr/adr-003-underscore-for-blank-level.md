# ADR 003: 空白レベルの目印にアンダースコアを採用

## Status

Accepted

## Context

本拡張機能には「空白レベル」がある。カードを作らずにレベルだけを1つ深くする書き方で、後でよいタスクを下の行へ押し下げるために使う。現在は「内容のない `- ` だけの行」を空白レベルとしている。実装では、パース前にその行へゼロ幅スペースを補い、リストのアイテムとして扱わせている。

しかし、この書き方はCommonMarkの解釈と食い違う。段落の直後に `-` だけの行が来ると、CommonMarkはそれをsetext見出しの下線と解釈する。次の例では、`[x] 拡張機能を…` の行が `<h2>` になる。

```markdown
- [x] 拡張機能を.vsixファイルから直接インストールする
  -
```

markdownlint 0.41でもこれをMD003違反として報告する。インデントの有無は無関係で、決め手は「直前の行が段落の途中か」と「マーカーが `-` か」である。空の子アイテムをCommonMarkで安全に書く唯一の形は、親本文との間に空白行を入れることだが、アウトラインとしては不自然になる。

このままでは、VSCodeのMarkdownプレビューやlintの結果が本拡張機能のマップ表示とずれる。利用者は同じファイルを両方で見るため、解釈の食い違いは避けたい。

## Decision

空白レベルは `- _` と書く方式を採用する。アイテムの本文をアンダースコア1文字だけにしたものを空白レベルとみなす。マップ表示では `_` を描画せず、カードも作らない。レベルだけを1つ深くする。

`_` を選んだ理由は、CommonMarkの解釈と衝突しないからである。`_` は1文字だけでは強調にならず、setext見出しの下線にもならない。本文のあるアイテムなので段落の直後でも子リストとして成立し、空白行を挟む必要がない。markdown-itで、段落直後の `- _` が子リストのアイテムになることを確認済みである。

従来の「内容のない `- ` だけの行」は廃止する。パース前にゼロ幅スペースを補う処理も削除し、`-` だけの行はCommonMarkの解釈にそのまま任せる。READMEの「空白レベル」の説明は `- _` に書き換える。

## Alternatives

### Alternative 1: 「`- ` だけの行」を続ける

現状のまま、内容のない `- ` だけの行を空白レベルとし、パース前にゼロ幅スペースを補う。利用者は何も書かなくてよく、見た目も最も軽い。しかし、CommonMarkとの解釈の食い違いは残る。VSCodeのMarkdownプレビューでは直前の行が見出しになり、markdownlintはMD003を報告する。「本拡張機能だけが独自に解釈する」ことを仕様として明記しても、利用者の混乱は減らない。このため採用しなかった。

### Alternative 2: 空白行を挟んだ空アイテム

親本文と `-` の間に空白行を入れる。CommonMarkで空の子アイテムが成立する唯一の形であり、プレビューとの食い違いはなくなる。しかし、アウトラインの途中に空白行が入る形は、アウトライナー風の編集と相性が悪い。1行1アイテムの前提が崩れ、markdownlintのMD007（インデント）も残る。このため採用しなかった。

### Alternative 3: `_` 以外の記号

`*` や `.` などの1文字を空白レベルの目印にする。`*` はsetextの下線にならないが、空アイテムでは段落を中断できず、直前の行の続きになる。本文を持たせるなら `_` と同じ扱いになるが、`*` はリストマーカーや強調と紛らわしい。`_` は行末の `+` と同じく「1文字の目印」として揃うため、`_` を選んだ。

## Confidence Level

確信度は高い。`- _` がCommonMarkで子リストのアイテムになることは、markdown-itで確認済みである。利用者の負担は1文字増えるだけで、行末の `+` と同じ「1文字の目印」として説明できる。実装はゼロ幅スペースの補完を `_` の判定に置き換えるだけで、変更は小さい。

次の状況になったら見直す。`_` が別の意味で使われる書き方が仕様に入ったとき。VSCodeのMarkdown拡張機能やmarkdownlintが `- _` を別の形で解釈するようになったとき。

## Consequences

良い結果。空白レベルの書き方がCommonMarkの解釈と一致する。VSCodeのMarkdownプレビューでも直前の行が見出しにならず、markdownlintのMD003も出ない。パース前のゼロ幅スペース補完がなくなり、実装が素直になる。

悪い結果。既存のアウトラインで「`- ` だけの行」を使っている箇所は `- _` に書き換える必要がある。書き換えないと、その行はCommonMarkの解釈に従い、意図しないマップになる。READMEと図の説明も更新が要る。

中立的な結果。空白レベルの目印が `_`、同じ帯に置く目印が `+` と、1文字の記号が2つになる。READMEの一覧で並べて説明する。
