# ADR 006: `-` だけの行を空欄のカードとして描画

## Status

Accepted

## Context

本拡張機能はストーリーマップをMarkdownのアウトラインから描く。利用者はアウトラインを1行ずつ書き足し、マップはそのたびに描き直される。

アウトラインを書く途中には、`- ` だけで本文のない行が自然に現れる。例えば、新しい行に `- ` と打った直後がそうである。

CommonMarkは、段落の直後にある `-` だけの行をsetext見出しの下線と解釈する。次の例では、`Task A1` の行が `<h2>` になる。

```markdown
- Task A1
  -
```

本拡張機能は「Story Map」見出しから次の見出しまでをマップの範囲としている。このため、`- ` だけの行を打った瞬間に、親のアイテムが見出しになり、ストーリーマップの節がそこで途切れる。後ろのアクティビティはすべて消える。入力のたびにマップが壊れて戻る。

ADR 003では、ゼロ幅スペースの補完を削除し、`-` だけの行の解釈をCommonMarkに任せた。当時は空白レベルの目印として `- _` を導入したため、`-` だけの行に役目がなくなっていた。その後、ADR 005で `_` は `^` と `v` に置き換えられた。`-` だけの行が編集中に現れる問題は、ADR 003の時点では考慮していなかった。

## Decision

`-` だけの行を、本文のない空欄のカードとして描画する方式を採用する。マーカー `-` の後に本文がない行は、空のリストアイテムとみなす。マップではそのアイテムを空欄のカードとして描き、子のアイテムはその1つ下のスライスに置く。通常のアイテムと同じ扱いである。

実装では、パースの前に `-` だけの行へゼロ幅スペースを補う。これによりmarkdown-itはその行をsetext見出しの下線ではなく、リストのアイテムとして読む。カードの本文を作るときにゼロ幅スペースを取り除き、カードを空欄にする。ゼロ幅スペースは拡張機能の内部だけで使い、ファイルには書き込まない。

この方式はADR 003の「ゼロ幅スペースの補完を削除し、`-` だけの行をCommonMarkに任せる」という決定を覆す。VSCodeのMarkdownプレビューやmarkdownlintの解釈とは食い違うが、その食い違いを受け入れる。理由は、編集中にマップが壊れないことを優先するためである。`-` だけの行は書き途中の状態であり、完成したアウトラインには残らない。完成後の解釈の一致より、入力中の安定した表示が重要である。

READMEには `-` だけの行の書き方を載せない。これは文法ではなく、編集中の状態への対処である。

## Alternatives

### Alternative 1: CommonMarkの解釈に任せ続ける

ADR 003のまま、`-` だけの行をsetext見出しの下線として扱う。プレビューやlintとの解釈が一致する。しかし、編集中に親のアイテムが見出しになり、マップがそこで途切れる。1行打つたびにマップが壊れる体験は避けたい。採用しなかった。

### Alternative 2: 見出しになったアイテムを本拡張機能側で元に戻す

パース後のトークンを調べ、`-` だけの行が原因で生じた見出しをリストのアイテムに戻す。ファイルの文字列には触れない。しかし、見出しの原因が `-` だけの行かどうかをトークンから判別するのは難しく、実装が複雑になる。ゼロ幅スペースの補完なら正規表現1つで済む。採用しなかった。

## Confidence Level

確信度は高い。`-` だけの行が編集中に現れることは、アウトラインを書く手順から明らかである。ゼロ幅スペースの補完はADR 003以前に使っていた実装であり、動作は確認済みである。変更は正規表現による置換と、カードの本文からの除去の2箇所だけで、小さい。

次の状況になったら見直す。markdown-itの更新で、ゼロ幅スペースだけのアイテムが空のアイテムとして扱われるようになったとき。`-` だけの行に別の意味を与える文法が仕様に入ったとき。

## Consequences

良い結果。編集中に `- ` と打っても、親のアイテムが見出しにならず、マップが途切れない。空欄のカードが場所を取るため、本文を書いても配置が動かない。

悪い結果。`-` だけの行の解釈が、VSCodeのMarkdownプレビューやmarkdownlintと食い違う。プレビューでは親の行が見出しになり、markdownlintはMD003を報告する。本拡張機能だけが独自に解釈する箇所が1つ残る。

中立的な結果。ADR 003の決定のうち、ゼロ幅スペースの補完を削除する部分がこのADRで覆される。`- _` の部分はすでにADR 005で置き換えられており、ADR 003の決定はすべて置き換えられたことになる。
