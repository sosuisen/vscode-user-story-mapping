# VSCode用 User Story Mapping 拡張機能

English version: [README.md](README.md)

VSCode上のアウトライン編集でユーザーストーリーマップを作成・編集できる拡張機能。

[User Story Mapping](https://jpattonassociates.com/story-mapping/) は Jeff Patton が提唱した手法で、プロダクト全体をユーザーの視点で見渡し、何から作るべきかを決めるためのもの。ユーザーの活動の流れに沿ってストーリーを左から右へ並べ、重要なストーリーほど上に置く。

Markdownの箇条書きで書いたアウトラインを、ユーザーストーリーマップとしてプレビュー表示する。専用の作図ツールでカードを1枚ずつ並べる必要はなく、書き慣れたアウトラインだけでマップが完成する。

## 使い方

1. ストーリーマップにしたいMarkdownファイル（.md）を開く。
2. 次のどちらかの方法でプレビューを開く。
   - エディタ右上の地図アイコン「Preview as User Story Map」を押す。
   - エディタ内で右クリックし、メニューから「Preview as User Story Map」を選ぶ。
3. プレビューがエディタの横に表示される。

### アウトラインの書式

基本の考え方は2つ。

- 時系列は左から右: ユーザーの大きな活動（アクティビティ）を、行動の流れの順に箇条書きする。マップでは横一列に並ぶ。
- 重要度はネストの深さ: アクティビティの下にユーザータスクをぶら下げ、重要なタスクほど浅く、そうでないタスクほど深くネストする。マップでは浅いタスクほど上の行に置かれる。

たとえば、次のアウトラインは、

```markdown
# Map Title

- Activity A
	- Task 1
		- Task 2
			- Task 3
	- Task 4
- Activity B
	- Task 5
```

次のマップとして描かれる。

![左がアウトライン、右がそれを描いたストーリーマップ](images/outline-to-map-basic.svg)

文法の一覧で参照している、もう少し詳しい例は次のとおり。

```markdown
# マップのタイトル

- アクティビティA
	- [ ] タスク1
		+ タスク1b
		- [x] タスク2
	- タスク3
- アクティビティB
	- 
		- タスク4
```

#### 文法の一覧

| 書き方 | マップでの表示 |
|---|---|
| 最初の見出し（`#`〜） | マップ冒頭のタイトル。なければ空のタイトル領域 |
| トップレベルの `- ` | アクティビティ。1行目（User Activity、緑の帯）に横一列に並ぶ |
| ネスト1段の `- ` | 最重要タスク。2行目（Walking Skeleton、赤の帯）に並ぶ |
| ネスト2段以降の `- ` | タスク。3行目以降（User Tasks、黄の帯）に、深さ＝行として並ぶ |
| 同じ深さの `- ` を連続 | 2つ目以降は右どなりの内部カラムへ分かれる（例のタスク3） |
| 内容のない `- ` だけの行 | 空白レベル。カードは作られず、レベルだけ1つ深くなる（例のタスク4はレベル2から始まる） |
| `+ ` のアイテム | 1つ上のレベル、つまり親タスクと同じセルに縦に積まれる（例のタスク1bはタスク1の下に付く） |
| `[ ] ` で始まるアイテム | 未完了タスク。⬜と影付きのカードになる |
| `[x] ` / `[X] ` で始まるアイテム | 完了タスク。✅と枠なし・影なしのカードになる |
| チェックボックスなし | 枠のみのカードになる |

- インデントはタブでもスペースでもよい（Markdown（CommonMark）の解釈に従う。タブ1個＝スペース4個相当）。
- 1つのファイル内でインデントの流儀は統一するのを推奨。

#### `+` でカードを積む

`+ ` のアイテムは、1つ上のレベルにある親タスクと同じセルに縦に積まれる。関係の深いカードをひとまとめにしたいときに使う。同じ深さの `- ` のアイテムは、積まれずに次の行へ置かれる。

```markdown
# Map Title

- Activity A
	- Task 1
		+ Task 1b
		+ Task 1c
		- Task 2
	- Task 3
```

次のマップとして描かれる。

![+ のアイテム Task 1b と Task 1c が Task 1 と同じセルに積まれ、Task 2 は次の行に置かれる](images/outline-to-map-plus.svg)

#### 空白レベル

内容のない `- ` だけの行は、カードを作らない。レベルだけを1つ深くする。重要度の低いタスクを下の行へ押し下げたいときに使う。例では、空白レベルが上にある Task 2 が、Task 4 より1行下に置かれる。

```markdown
# Map Title

- Activity A
	- Task 1
		- 
			- Task 2
- Activity B
	- Task 3
		- Task 4
```

次のマップとして描かれる。

![空白レベルのために Task 2 が Task 4 より1行下に置かれる](images/outline-to-map-blank.svg)

## 推奨環境

快適なアウトライン編集のため、次の併用を推奨する。

- 拡張機能「[Markdown All in One](https://marketplace.visualstudio.com/items?itemName=yzhang.markdown-all-in-one)」をインストールする。
- キーバインディングをアウトライナー風に変更する（項目の入れ替え・インデント操作など）。

## 動作環境

- VSCodeデスクトップ版（Windows/macOS/Linux）。
- Web版（vscode.dev）は対象外。

## インストール

当面はGitHubのリリースページから `.vsix` ファイルをダウンロードし、手動でインストールする。安定したら、VSCode Marketplaceへの公開を目指す。

## 開発

```powershell
npm install
```

- **実行**: VSCodeでこのフォルダを開き、F5で拡張機能開発ホストを起動する。
- **watchビルド**: `npm run watch`
- **テスト**: `npm test`（Mocha + `@vscode/test-cli`。テスト用VSCodeが起動する）
- **パッケージング**: `npm run package` で本番ビルドを生成する。

### ドキュメント

- `docs/storymap.md` — 本プロダクト自身のストーリーマップ（拡張機能が完成するまでの暫定運用）
- `docs/adr/` — アーキテクチャ上の決定の記録（ADR）
- `docs/plans.md` — 現在TDDの対象としている作業用todo
- `test/test.md` — 動作確認用のテストマップ
